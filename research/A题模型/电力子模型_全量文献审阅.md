### 0.3 最重要的五个缺口

1. **`P_grid` 被当成正常运行下的常数。** 文献中的 hosting capacity 是“在给定故障集合、电压/热稳定和合同条件下可接入的容量”，不是排队容量、变电站铭牌或一次潮流结果。最直接的方法来源是 `42`（EirGrid 逐站 N-1/N-1-1 流程）、`41`（Wu 等的数据中心 N-1 hosting capacity）和 `38`（firm/flexible capacity）。
2. **风电 `alpha=min(出力/装机)` 不是 ELCC。** 它只在“孤立、无其他电源、要求全考察期恒定负荷”这一特殊口径下成立；有公共电网、储能或其他机组时，应报告 ELCC 或按同一可靠性目标计算的容量价值，不能把最低出力比例当作系统容量信用。`32`、`36`、`37`、`35` 提供了定义、算法和数据要求。
3. **光储附录是确定性 MILP，不是概率可靠性容量价值。** 它能回答“给定一段历史出力和完美预测，最大恒定附加负荷是多少”，不能回答“在故障、负荷和天气不确定性下能稳定承载多少”。`39` 说明储能容量价值取决于持续时间和缺电事件的前后顺序；`35` 提供 EUE/LOLE/EFC/ELCC 的统一口径。
4. **没有把可延迟工作任务写成能量守恒约束。** `41` 给出了可延迟批处理工作的到达、延期、完成和期末清零约束；`25`、`08`、`24` 给出了可中断/可移负荷的现场与情景证据。负荷柔性只能增加“在限制时段可让出的容量”，不能不加约束地并入 firm capacity。
5. **没有把“已排队、已签协议、已送电、已建成”分开。** `01`、`05`、`07`、`34`、`24`、`27` 都说明接入容量是合同、工程研究、设备和建设状态的联合结果；NERC 的 Tier 1/2 也只是规划成熟度，不是已交付容量。

## 1. 现有 v2 模型逐式审阅

### 1.1 总功率与 IT 功率

当前模型是：

```text
P_total = P_grid + P_self
P_E     = P_total / k
```

它在以下条件下可以作为**正常运行、确定性、单场景**的容量上界：

- 公共电网和自建电源可以同时向同一园区注入，且没有共同的关口/线路瓶颈；
- `P_grid` 是接入研究或合同确认的持续有功功率，而不是排队容量或变电站铭牌；
- `P_self` 是同一考察期、同一运行方式下可同时交付的净功率；
- `k` 是设计满载工况的设施总功率/IT 功率，而不是只在年度平均意义上成立的 PUE；
- 不要求承受 N-1、N-1-1、公网停电、燃料中断或极端天气。

文献要求补上的两个接口是：

```text
P_grid,t <= C_grid^contract
P_grid,t <= C_grid^N1
P_grid,t + P_self,t <= C_pcc          （若共用一个并网关口）
P_fac,t = k_design,t * P_IT,t
```

其中 `C_pcc` 是园区关口/专线的共同容量。若自建机组只能向公共电网售电、不能可靠地向园区供电，则不能把它直接加到 `P_self`；若自建机组与电网共用一条受限线路，则 `P_grid + P_self` 会重复计算通道能力。

### 1.2 `P_grid`：接入容量不是单一数字

文献中的容量至少有四层：

| 口径 | 含义 | 不能做什么 |
|---|---|---|
| `MIC` / `MEC` | 最大进口/出口容量，通常以 MVA 计 | 不能直接当 MW、IT MW 或 firm MW |
| 排队/申请容量 | 开发商提出但未完成研究的容量 | 不能当已签合同或已送电容量 |
| 接入研究容量 | 在指定网络、故障集和运行方式下允许的容量 | 不能跨站点相加 |
| 已送电/可运行容量 | 设备、保护、合同和调试均完成的容量 | 不能自动等于全年每个时刻可用的 firm capacity |

`01_CRU2025236_Ireland_Grid_Connection` 明确区分 `MIC` 与 `MEC`，并规定大用户的自备/近区电源要按 de-rated capacity 覆盖 MIC；`05_EirGrid2026_DC_Connection_Process` 进一步把“数据中心不能先于关联发电项目投运/爬坡”写成流程约束。`42` 则给出逐站计算方法：在 0.90 功率因数下逐级增加负荷，对 N-1、N-1-1 或双回线故障逐一校核，越限后按 10 MW 步长回退，取所有情景的最低值；报告明确说各站结果不可相加。

因此，若没有场址接入研究，`P_grid` 只能标为“初筛上界”，不能写成“该站可接入 MW”。如果只有 `MIC`，最多只能写：

```text
P_grid^contract = MIC_MVA * pf
```

其中 `pf` 必须显式给出；`42` 的无功关系是 `Q=P*tan(arccos 0.90)=0.4843P`，不是把 MVA 直接当 MW。

### 1.3 火电：`N × p_net` 的方向正确，但 `p_net` 需要成为条件函数

当前式：

```text
P_j = N_j * p_j^net
```

适合做“已建成、供气/冷却/许可均满足”条件下的容量上界。需要补充的乘子包括：

```text
p_net(T,z,age,water)
  = p_ISO
    * f_temp(T_amb)
    * f_alt(z)
    * f_age(age)
    * f_availability
    * f_cooling(water)
```

关键文献证据：

- `54_EPA_CHP_Gas_Turbines`：ISO 条件为海平面、59°F；示例 7.5 MW 燃机在 100°F 时功率约为额定的 80%、效率下降约 8%，40°F 时约为 107%；海拔升高会按空气密度下降的比例降额；部分负荷效率明显下降。可用率样本约 93.49%–96.12%，强迫停运率约 1.37%–2.89%。
- `51_Jones2025_Thermoelectric_Usable_Capacity`：热电可用容量受可取水量、热耗散和环境流量/水温共同约束；不能只用装机减去一个固定厂用电。
- `53_IFC2008_Thermal_Power_EHS`：取排水、混合区、温升、环境流量和许可构成可行域边界，不是容量公式；`>50 MWth`、取水流速 `0.5 ft/s` 等是其适用/设计背景，不可当作所有项目的法律限额。
- `45_REopt_Lite_Manual` 和 `48_HOMER_Pro_Engineering_Manual`：可作为园区级容量筛选工具，但都明确有“无详细潮流、无冗余/安全系数、电网无限或每年一次停电”等简化，不能替代接入研究。

因此，现有 `unit_net_mw` 应改为“基准净功率 × 当地条件折减”的可追溯参数，而不是一个不随季节变化的常数。若没有当地曲线，至少要报告 `T`、海拔、冷却方式和可用率的敏感性。

### 1.4 风电：`alpha` 的严格含义与失效条件

当前式：

```text
P_wind = alpha * A_wind * rho_wind
alpha = min_t(P_wind,t / X_wind)
```

它在数学上对应一个非常保守的确定性承诺：

> 若风场必须单独为一个恒定负荷供电，且不允许其他电源、储能或可中断负荷补位，那么能保证的恒定功率不超过考察期内风场最低净出力。

这不是电力系统规划中的 ELCC。`32_Keane2011_Capacity_Value_of_Wind` 给出的标准方法是：

1. 用常规机组的容量停运概率表（COPT）和不含风电的逐时负荷计算基准 `LOLE`；
2. 把风电逐时出力作为负负荷叠加，得到净负荷；
3. 在所有小时增加一个恒定负荷 `ΔL`，重复计算，直到 `LOLE` 回到基准；
4. 使风险回到基准的 `ΔL` 就是 ELCC。

即：

```text
R(S + wind, D + ΔL) = R(S, D)
```

`32` 还强调：必须使用同一时期、同一区域、同步的负荷与风电序列；不能用年容量因子或两状态模型代替；ELCC 会随系统规模、渗透率、可靠性目标、风光与负荷相关性、地理分散程度变化。`36_Hasche2011_Wind_Data_Requirements` 进一步给出数据要求：至少 4–5 年逐时数据、40–50 个分布站点；只用 1 年可能低估约 30% 或高估约 20%。`35_NREL2021_PRAS` 把 ELCC/EFC 纳入统一的资源充足性框架。

结论：

- **孤立站点、无电网、无储能、要求恒定负荷**：可以保留最低出力口径，但应改名为“observed-period minimum-output firm fraction”，不能叫 ELCC。
- **有公共电网或系统资源**：应使用 ELCC 或至少做逐时功率平衡；`alpha` 只作为情景参数，不能把文献中的 5%–30% 直接套到项目上。
- **有储能**：风光和储能必须联合求解，不能把风电的 `alpha` 与储能 MILP 各自独立相加。

### 1.5 光伏与储能：确定性 MILP 的有效范围

当前附录 A 求的是：

```text
max L
s.t. r_t + d_t >= L + c_t
     e_(t+1) = e_t + eta_c c_t Δt - d_t Δt / eta_d
     0 <= c_t <= C_max
     0 <= d_t <= D_max
     0 <= e_t <= E_usable
     e_(T+1) = e_1
```

它适合回答：

> 给定一段历史风光序列、完美预测、固定电池参数和周期首尾电量相同的条件下，最大可维持的恒定附加负荷是多少？

它的三个边界必须写清楚：

1. **不是概率可靠性指标。** 它没有机组/线路强迫停运、天气预测误差、负荷不确定性，也没有 `LOLE/EUE` 目标。
2. **不是储能容量价值。** `39_Sioshansi2014_Storage_Capacity_Value` 说明储能容量价值取决于持续时间、缺电事件的前后顺序和补电能力；用最大发电能力近似会高估，短时储能最多可高估约 22%。其算例的 ELCC 为：1 h 36.26%、2 h 49.76%、4 h 66.75%、8 h 84.74%、10 h 89.48%。
3. **周期首尾条件会改变结果。** 若首尾电量不能自由选择，或者要求保留应急能量，MILP 的 `L` 会下降；当前实现把初始电量作为可自由选择的变量，这一点必须在论文中说明。

`33_Goiri2013_Parasol_GreenSwitch` 的原始模型还包含 `BattBrown`，即允许电网给电池充电；当前 v2 附录只核算自建电源增量，因此代码选择“禁止电网充电”。这是一个重要的口径选择，不是文献本身的唯一答案：若允许电网充电，必须把电网电量、容量和排放计入，不能让它绕过 `P_grid`。

### 1.6 `P_E = P_total / k`

这一式可以用，但 `k` 不能和年度 PUE 混为一谈。文献中的定义是：

```text
annual PUE = E_facility / E_IT
k_design   = P_facility,design / P_IT,design
```

`24_IEA2025_Energy_and_AI` 在 PDF p.53 和 p.269 明确区分 `installed IT capacity`、`total installed capacity` 和 `maximum designed capacity`；PUE 是能耗比，且同一报告给出 2024 年全球平均 PUE 1.41、2030 年 Base Case 1.29，Hyperscale 2024 年 1.14。`40_Chen2023_Cooling_Economization` 也把 PUE 写成年度 `P_site/P_IT`，并给出冷却方式导致的差异；`07_JLARC2024_Virginia_Data_Centers` 明确说 PUE 不衡量计算效率。

因此：

- 容量约束用 `k_design`；
- 年度电量/水/碳核算才用年度 PUE；
- 若只有年度 PUE，必须把它标为近似，并给出满载辅助用电占比接近全年平均的条件；
- `2N` UPS 的 50% 负载率、UPS 15–20 分钟桥接、CRAC 的 N+1 冗余属于设备级可用性，不是“可以多带 50% IT”或“UPS 可以当数小时储能”。

`46` 的 `A=MTBF/(MTBF+MTTR)` 和 `31` 的 2N/N+1 规则可用于设施可靠性建模，但不能替代电网 N-1、燃料持续时间和孤岛切换。

## 3. 按子模块整理的关键证据

### 3.1 接入容量、合同和 N-1

#### EirGrid/SONI 的逐站方法（`42`）

`42` 的流程可以直接作为“场址 hosting capacity”模板：

1. 固定研究年、夏季/冬季运行方式和发电可用性；
2. 在测试站按 0.90 功率因数逐步增加负荷；
3. 对 N-1、N-1-1 或双回线故障逐一进行 AC 潮流筛选；
4. 记录热过载或电压越限；
5. 若最大容量越限，则从 0 MW 开始按 10 MW 步长增加，取越限前一步；
6. 取所有调度和故障情景的最低值；
7. 结果只对测试站和该研究年有效，不能把多个站的结果相加。

这比“变电站还有多少 MVA”更接近第一问的“能接入多少 MW”。但它仍有边界：只评估输电网，不含配电网；研究年是 2025；不能直接移植到其他国家和地区。

#### Wu 等的数据中心 N-1 模型（`41`）

`41` 把数据中心连接容量 `H` 和可延迟工作量耦合起来：

```text
W_t^0 = H * a_t
W_t^B0 = alpha_t^B * W_t^0
0 <= w_t <= mu * u_bar * m_t
0 <= m_t <= rho * H
p_t^IT = p_idle*m_t + ((p_peak-p_idle)/mu)*w_t
p_t^DC = eta * p_t^IT
```

并用 LODF 表示支路故障后的潮流：

```text
f_(l,t)^(c) = f_(l,t) + L_(l,c) * f_(c,t)
-F_l <= f_(l,t)^(c) <= F_l
```

算例参数为 `eta=1.20`、`p_idle=1.3 kW/server`、`p_peak=1.9 kW/server`、`mu=500 workload units/h`、`u_bar=0.80`、批处理占总工作量 20%，使用 1,464 小时数据。IEEE 118 节点系统中，Bus 92 的 N-1 容量从非柔性 3,804.3 MW 增至柔性 4,736.5 MW，增益 932.2 MW（24.5%）；Bus 77 从 4,739.0 MW 增至 5,610.9 MW，增益 871.9 MW（18.4%）。4 小时延迟窗口获得 6 小时窗口增益的 90.9%，说明延迟收益递减。

该文的重要结论不是“柔性一定增加 20%”，而是：

- N-1 下的可用容量取决于接入点相对故障区域的位置；
- 同样的负荷柔性在不同站点价值不同；
- 柔性必须写成“在截止期内完成全部工作”的时序约束，不能只写一个可削减 MW。

#### Li 等的 firm/flexible capacity（`38`）

`38` 将容量分成：

```text
c_i^f : 在不确定负荷范围内都要满足网络约束的 firm capacity
c_i^r : 允许一定 blackout risk 的 flexible capacity
c_i^c = c_i^r - c_i^f : 通过接受风险释放的增量
```

其 firm 模型含节点取电限制和 DC 潮流：

```text
c_i^f + l_i <= q_i
b_lower <= S(c^f + l) <= b_upper
```

flexible 模型把约束改成 `CVaR_alpha`：

```text
CVaR_alpha[c^r + l] <= q
CVaR_alpha[S(c^r + l)] <= b_upper
CVaR_alpha[-S(c^r + l)] <= -b_lower
```

其中 `r=1-alpha` 是可接受失负荷风险。该文的 4 节点算例给出 `c_f3=10`、`c_f4=10`、`c_r3=16.3`、`c_r4=15.6` MW；这只是示例，不能当作项目容量。它的价值在于把“保证容量”和“可中断容量”分开，而不是把 flexible capacity 直接加进 firm capacity。

#### 接入时序和队列

- `24` PDF p.94：美国平均并网排队 1–3 年，北弗吉尼亚最长 7 年，德国最长 7 年，英国 5–7 年，荷兰最长 10 年，日本关东超过 5 年，都柏林暂停到 2030 年。
- `24` PDF p.95：发达国家新建输电线路约 4–8 年，新兴经济体约 2–4 年；2024 年变压器订单积压增长超过 30%，价格指数较 2020 年约上涨 1.5 倍。
- `24` PDF p.96：约 20% 的 2030 年前规划数据中心容量面临并网延迟风险。
- `01`、`05`：数据中心 connection offer 标准约 7.5 个月，最长 18 个月，取决于关联发电项目状态；`05` 还规定数据中心不能先于关联发电项目投运/爬坡。
- `07`：单个数据中心建筑约 12–18 个月，campus 完全建成常需 5 年以上；新建发电通常 5 年以上，大型输电常 5–7 年。

因此，静态模型至少要把“评估年份”和“该年已可用容量”分开。若论文写 2030 年，就不能把 2031 年才投运的输电或机组算进去。

### 3.2 可靠性和容量价值

#### 指标口径

NERC 2025 LTRA（`27`）使用的风险分级口径是：

- High Risk：年 `LOLH > 2.4 h/y` 或年归一化 `NEUE > 20 ppm`；
- Normal Risk：`LOLH < 0.1 h/y` 且 `NEUE < 2 ppm`；
- 两者之间为 Elevated Risk。

这是 NERC 的风险分级，不是全球法律上限，也不是某个项目的合同可靠性指标。引用时必须保留“北美、2026–2035、2025 年数据快照”的上下文。

PRAS（`35`）给出：

```text
EUE = sum_t E[unserved energy_t] * Δt
LOLE = sum_t P(load > available generation at t)
```

以及 ELCC/EFC 的统一思想：

```text
R(S + s, D + ΔL) = R(S, D)
```

其中 `R` 可以是 LOLE、EUE 或其他同一基准风险指标。关键不是指标名称，而是基准系统、负荷年份、故障模型和统计期必须一致。

#### 风电 ELCC

`32` 的标准负负荷法：

```text
LOLP_t^base = F_C(l_t)
LOLP_t^wind = F_C(l_t - w_t)
```

通过增加恒定负荷 `ΔL` 使加入风电后的 `LOLE` 回到基准，`ΔL` 即 ELCC。它不能只用年容量因子，因为风光出力与负荷峰值的同步性决定了实际容量价值。`32` 还指出 ELCC 受系统规模、渗透率、可靠性目标、维护安排、地理分散和输电可用性影响。

`36` 给出了数据要求：

- 爱尔兰案例使用 74 个风电场、最长 10 年逐刻钟数据；
- 1 小时与逐刻钟结果偏差小于 1%，3 小时分辨率可达 5%；
- 只用 1 年数据可低估约 30% 或高估约 20%；
- 4–5 年后最大偏差通常小于 10%；
- 站点太少会低估容量价值，40–50 个分布站点才较好代表区域风电。

#### 光伏 ELCC/ECP

`37` 的 100 MW-DC 光伏在 STC 下为 83.4 MW-AC，使用 WECC 1998–2005 年负荷和 14 个站点，基准 LOLE 0.1 day/year（约 2.4 h/year）。固定轴 PV 的 Table 3 结果为 ECP 约 55.8%–75.1%、ELCC 约 51.8%–69.7%；报告跨跟踪方式的总体结论为 ECP 约 61%–92%、ELCC 约 52%–86%。这再次说明 ECP 和 ELCC 不能混用，且结果依赖系统与渗透率。

#### 储能容量价值

`39` 的核心动态规划思想是：某小时储能能否放电，不仅取决于功率，还取决于此前是否已经被缺电事件耗尽，以及之后能否补电。其 Table II 以 80 MW 净放电容量为基准，给出：

| 储能时长 | ECP | ELCC |
|---:|---:|---:|
| 1 h | 40.74% | 36.26% |
| 2 h | 55.53% | 49.76% |
| 4 h | 74.63% | 66.75% |
| 8 h | 93.74% | 84.74% |
| 10 h | 97.92% | 89.48% |

这组数不能直接移植到本项目，但可以支持两个定性结论：短时储能的容量价值远低于铭牌功率；用最大发电能力近似会系统性高估能量受限储能。

### 3.3 数据中心负荷和设施功率

#### IT 功率的服务器级表达

`09` 和 `24` 都使用或引用了服务器功率曲线：

```text
P_server = P_idle + (P_peak - P_idle) * u
```

`09` 的情景假设为 `P_idle=0.23*rated`、`P_peak=0.88*rated`，推理利用率约 25%、训练约 72%，基准组合 30% 训练、70% 推理；这些是情景参数，不是园区实测。`24` 的 PDF p.256 使用 `E=(P_max-P_idle)u+P_idle` 的服务器电量形式。

`41` 则把服务器数量、处理率和工作量写成：

```text
0 <= w_t <= mu * u_bar * m_t
p_IT = p_idle*m_t + ((p_peak-p_idle)/mu)*w_t
p_DC = eta*p_IT
```

这条链比单取一个“平均 PUE × 额定 IT MW”更适合第一问，因为它把任务量、服务器数量和设施功率连了起来。

#### 年度 PUE、峰值倍率和设施容量

`24` 的定义（PDF p.53、p.269）应作为口径基准：

- `installed IT capacity`：已安装的服务器、存储和网络设备容量；
- `total installed capacity`：IT 容量加辅助设备功率容量；
- `maximum designed capacity`：如果机房装满服务器时的最大设计容量；
- `PUE`：总设施电量/IT 电量，不是峰值功率倍率；
- `utilisation rate`：实际使用的计算资源比例，不等于电功率负载率。

`07` 的 PUE=1.3 例子说明“IT 1.0、其他建筑系统 0.3”是年度能耗分解；`40` 的 PUE 1.65 也是年度值；`31` 的 UPS/CRAC 规则是设备冗余，不是设施功率倍率。因此，论文中最好同时给出：

```text
k_design = P_facility,design / P_IT,design
PUE_annual = E_facility / E_IT
```

并在附录说明两者何时可以近似相等。

#### 2N、UPS 和备用电源

- `46`：2N 系统负载率不应超过 50%；UPS 电池通常只承担切换过渡，标准表值常见 15 分钟；有柴油后备时可延长，但静态 RBD 不能替代实际持续时间。
- `31`：UPS 电池备用 15–20 分钟通常足够，不建议超过 30 分钟；每 5–6 台 CRAC 配 1 台 N+1 备用；高可用冷却可用 4–15 分钟热储维持。
- `55`：有意孤岛需要岛内功率平衡、电压/频率支撑、保护/接地、黑启动/燃料持续和回并条件；“有 UPS 或柴油机”不等于可长期孤岛运行。
- `45`、`48`：REopt/HOMER 可以模拟停电和 critical load，但 REopt 每年只模拟一次停电、没有冗余/安全系数；HOMER 的 grid outage 是购售电禁止，不是网络 N-1。

这三类设备必须在模型中分层：

```text
UPS: 秒级到分钟级桥接
备用发电/储能: 小时级到日级
N-1 网络容量: 故障状态下的持续供电能力
```

不能把三者折成一个“可用率”或一个“备用 MW”。

### 3.4 可延迟负荷与需求响应

`41` 的批处理平衡是最适合第一问的写法：

```text
q_(t,tau) >= 0,  tau - t <= K
sum_t w_t^B = sum_t W_t^B0
```

其中 `q_(t,tau)` 是第 `t` 小时到达、延迟到 `tau` 小时执行的工作量；期末必须完成全部工作，不能把延期当成减少总电量。`41` 的结果还说明，容量收益取决于限制时段、延迟窗口和恢复时段，不能只看一个“可削减百分比”。

现场证据：

- `25`：256-GPU 集群在 APS/SRP 峰时事件中削减 25% 功率、持续 3 小时、15 分钟升降坡；Flex 1/2/3 分别对应吞吐下降最多 10%/25%/50%。
- `08`：某案例在峰值碳时段把 VCC 降低约 50%，对应功率约降 8%、持续 3–6 小时；全 fleet 平均仅 1–2%。
- `24`：冷却占数据中心负荷约 10%–30%；约 30%–50% 的工作负载可延迟；2035 年技术柔性潜力约 50 GW；若只为柔性过度建设加速服务器，成本约 700 USD/MWh 的转移电量。

模型中可写：

```text
0 <= P_shed,t <= P_DR * z_t
z_t in {0,1}
连续削减时长、日/年频次、通知时间、恢复时间均设上限
E_task completion = E_task arrival
```

并把 `P_DR` 标为“事件型/条件型容量”，不要把它直接加到 `P_firm`。

### 3.5 网络潮流与 N-1

`43_MATPOWER_Manual` 提供标准 AC/DC OPF 字典：

```text
min f(x)
s.t. g(x)=0, h(x)<=0
```

AC 版本含节点有功/无功平衡、电压幅值和支路 MVA 限额；DC 版本是线性化有功潮流。其连续潮流 `f(x,lambda)=g(x)-lambda*b=0` 可用于求静态负荷极限，`makeLODF` 可生成线路故障分布因子，但 `LODF/DC` 结果必须回代 AC，桥支路和孤岛故障不能直接套普通 LODF。

`44_Farivar2013_Branch_Flow` 提供分支潮流/SOCP：

```text
l_ij >= (P_ij^2 + Q_ij^2) / v_i
```

但 Theorem 1 的精确性依赖“负荷没有上界”。第一问把新增负荷上限当成决策变量，恰好违反这个条件；因此 SOCP 只能作为近似或保守模型，必须做 AC 回代和角度/电压检查。

`52_PyPSA` 提供节点 KCL、可扩展容量、储能和 LOPF/SCLOPF；`50_PyPSA_Earth` 提供开放网络、资源和面积密度接口；`48_HOMER` 提供 purchase/sale capacity 和 outage，但没有节点潮流。它们适合做不同层级的模型，不能互相冒充。

### 3.6 水、土地和冷却对电力容量的反馈

这一部分不是第一问的主目标，但会改变可用电力，因而必须保留接口：

- `51`：热电可用容量受冷却水取用、热耗散、环境流量和排放温度约束；`W_max` 由可取水量与温升共同限制，`ΔT_max` 等参数必须本地化。
- `53`：取排水、混合区、温升、环境流量、土地/燃料/电网接入和许可构成火电可行域；指南不是一组通用排放常数。
- `15`：发电技术水因子必须区分取水与耗水、冷却塔与直流冷却；例如天然气 CC 冷却塔耗水中位数约 205 gal/MWh、干冷约 2 gal/MWh（×3.785 转 L/MWh）；煤冷却塔约 687、直流约 250 gal/MWh。
- `12`、`13`、`21`、`14`：数据中心水足迹、发电上游水、水风险分数和 AWARE 加权只能作为水模块接口；`0–5` 的风险分数不是 m³，也不是 MW。
- `16`、`17`、`18`：发电用地必须区分 `direct footprint` 与 `total/spacing`、`ha/TWh/y` 与 `acres/MWac`；风电永久 direct footprint 约 0.3±0.3 ha/MW，总占地面积可达 9–100 ha/MW。
- `40`、`28`：冷却方式和微气候会改变 PUE/WUE，但年度 PUE 不能直接当峰值 `k`。

在第一问中，建议只保留两个接口：

```text
P_thermal_available <= f_water(Q, T, permit)
A_generation <= A_available - A_site - A_grid
```

不要把水/土地的完整多目标模型塞进电力容量方程；否则会把不同功能单位混在一起。

## 4. 建议的模型升级顺序

### P0：在论文中必须先做的口径修正

1. **定义容量词汇表。** 明确 `MIC/MEC`、`P_grid`、`C_grid^N1`、`C_self`、`P_fac`、`P_IT`、`C_firm`、`C_flex`、`P_E` 的区别和单位。
2. **把 `P_grid` 改成条件容量。** 至少写 `P_grid <= min(MIC_MVA*pf, C_N1)`；没有 N-1 数据时，明确只报告正常运行上界。
3. **把 `k` 改成 `k_design`。** 年度 PUE 只用于电量/水/碳；如果只能用 PUE，标为近似并做敏感性。
4. **给 `alpha` 改名并写边界。** 它是“考察期最低净出力/装机”的确定性比例，不是 ELCC；有电网时改用 ELCC 或逐时平衡。
5. **把负荷柔性写成任务能量守恒。** 若引入可延迟工作，必须包含到达、延期、截止、期末完成和恢复功率；不能只乘一个 0.8 或 0.75。
6. **把 firm 和 flexible 分栏报告。** 不把可中断负荷、UPS 分钟级支撑和 N-1 备用加成一个“可靠 MW”。
7. **把建设年份写进变量。** 评估 2030 年时，只纳入该年前实际可投运的发电、输电和变压器。

### P1：在不重构代码的前提下可加的模型块

- **N-1 筛查：** 用 EirGrid 式逐故障回退或 Wu 式 LODF；先用 DC 潮流筛选，关键方案再做 AC 回代。
- **资源充足性：** 用 PRAS 类框架计算 `LOLE/EUE`，报告 ELCC/EFC；至少给出一个基准风险目标和敏感性。
- **储能容量价值：** 保留现有 MILP 作为“确定性恒定负荷上界”，另用 ELCC/DP 或 PRAS 计算概率容量价值；两者并列，不混为一个数。
- **火电降额：** 把温度、海拔、可用率、冷却水/排热作为乘子或情景；燃料热值统一 LHV/HHV。
- **接入时序：** 增加 `A_i,t` 或可用年份；区分排队、已签协议、在建、已送电。
- **共同关口：** 若电网和自建电源共用线路，增加 `P_grid,t + P_self,t <= C_pcc`。

### P2：有真实场址数据后再做

- 全 AC OPF、电压/无功、保护配合和 N-1-1；
- 多园区联合 hosting capacity，避免把单站结果相加；
- 孤岛切换、黑启动、频率/电压支撑和回并；
- 概率天气/负荷/故障场景、储能老化和燃料供应中断；
- 水/土地/碳多目标优化与公平性分配。

### 不建议做的事

- 不要用全球 415/945 TWh、美国 5,050 MW 或爱尔兰 5.8 GW 直接推某个场址的 MW；
- 不要用年度 PUE 直接代替峰值 `k`；
- 不要把 ELCC 的百分比跨系统、跨年份、跨渗透率移植；
- 不要把排队容量、变电站铭牌、合同容量、已送电容量混成一个 `P_grid`；
- 不要把储能铭牌功率、UPS 分钟级备电、需求响应和 N-1 备用相加；
- 不要为了“用满文献”而给低相关文献强行编造模型角色。

## 7. 重复、冲突和引用纪律

### 7.1 已确认的重复

- `ref/33` 与 `research/A题文献库/01_公开原文/29_Goiri-Parasol-GreenSwitch.pdf`：同一篇 ASPLOS 2013 论文，仅版式/页码不同。规范化文本比较为 `SequenceMatcher.ratio()=1.0`，非空白字符数均为 85,448；公式、参数、实验结果一致。不能写成“两个版本有不同公式”。
- `research/A题文献库/01_公开原文/` 其余 26 个 PDF 与 `ref/` 精确重复，不构成新的独立证据。

### 7.2 必须保留的口径冲突

| 冲突 | 错误做法 | 正确做法 |
|---|---|---|
| 容量 | 把 MIC、MVA、IT MW、设施 MW、firm MW 混写 | 每个“容量”都加限定词和单位 |
| PUE | 用年度 PUE 直接当峰值 `k` | 容量用 `k_design`；年度 PUE 只做电量 |
| 风光 | 用容量因子或年发电量代替 ELCC | 容量信用用 ELCC/EFC；电量用 CF |
| 储能 | 用铭牌功率当容量价值 | 同时约束功率、能量、SOC、持续时间和补电 |
| 负荷柔性 | 把可削减百分比直接加到 firm capacity | 写事件、持续时间、通知、恢复和任务完成约束 |
| 水 | 把取水当耗水、现场水当上游水 | 区分 withdrawal/consumption、direct/indirect |
| 土地 | 把 spacing 当永久 footprint | 区分 direct/total、footprint/spacing、MW/GWh |
| 火电 | 不区分 LHV/HHV | 固定基准；天然气约差 10% |
| 潮流 | 用 DC/LODF 直接作最终结论 | DC 筛选后做 AC 回代和电压检查 |
| 站点结果 | 把多个站点的 hosting capacity 相加 | 联合潮流/故障集重算；单站结果不可加 |
| 建设状态 | 把排队、Tier 2、签协议当已送电 | 用已送电/可运行状态和投运年份 |
| 可靠性 | 把 UPS 可用度、N-1、LOLE 混为一个数 | 分层分别报告 |

## 8. 建议的下一步

### 8.1 先确定研究边界

在写数值结果前，需要团队先固定：

1. 研究对象是**单个园区**还是**区域算力网络**；
2. 服务承诺是**正常运行容量**、**N-1 容量**，还是**含公网停电的孤岛容量**；
3. 可靠性目标是 `LOLE`、`EUE` 还是合同可用率；
4. 评估年份和该年已投运的发电/输电/变压器；
5. 是否允许可延迟工作，允许的延迟窗口、SLA 和恢复功率；
6. 电网和自建电源是否共用关口，是否允许向电网反送。

没有这六个选择，`P_grid + P_self` 只能是一个没有明确服务承诺的“功率上界”，不能直接回答第一问的“可持续规模”。

### 8.2 需要补的外部数据

- 场址变电站的 `MIC/MEC`、短路容量、主变容量、N-1/N-1-1 研究或可开放容量；
- 至少 4–5 年逐时负荷、风速、太阳辐照、温度和可用出力；
- 自建机组的型号、ISO 曲线、海拔/温度修正、最小负荷、爬坡、可用率和燃料曲线；
- 冷却水可取量、排放温度、环境流量和许可；
- 输电/并网/设备交付的关键路径时间；
- 真实园区的 `k_design`、PUE、WUE、2N/N+1 配置和 UPS 桥接时间。

### 8.3 建议先做的敏感性，而不是先改代码

| 参数 | 建议范围 | 目的 |
|---|---|---|
| `k_design` | 1.10–1.65（按设施类型） | 观察 PUE/冷却假设对 IT MW 的影响 |
| 年度 PUE 与峰值 k 的差异 | 以 PUE 为近似、再设 ±10%–20% | 量化年度口径误用 |
| 风电 `alpha` | 0%–30%，并与 ELCC 情景并列 | 展示最低出力口径与系统容量价值的差 |
| 光伏 ELCC | 10%–70% | 观察渗透率和跟踪方式 |
| 储能时长 | 1–10 h | 观察能量受限导致的容量价值下降 |
| N-1 与正常状态 | 两套结果并列 | 量化事故暴露和位置效应 |
| 柔性比例 | 0/10%/25%/50%，持续 3–6 h | 观察 firm/flexible 的差别 |
| 建设年份 | 2027/2030/2035 | 观察排队和工期对可用容量的影响 |
| 水/冷却约束 | 充分供水/受限/干冷 | 观察火电净功率下降和方案排序变化 |

### 8.4 对论文写法的建议

建议把第一问结果写成四个层次，而不是一个孤立数字：

```text
正常运行、合同容量下的上界
N-1 安全约束下的 hosting capacity
含可延迟负荷的 flexible capacity
含概率可靠性目标的 firm capacity / ELCC
```

每一层都注明：电网状态、故障集合、可靠性目标、时间序列长度、天气年份、`k` 的口径、是否允许需求响应、是否允许孤岛。这样既能利用文献，又不会把不同文献的数字拼成一个看似精确、实际上不可比的 MW。
