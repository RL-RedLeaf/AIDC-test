## 摘要（第 1 页）

近年来，基于生成式、多用途 AI 系统的商业 AI 产品迅速流行，承诺以统一方式把机器学习（ML）模型嵌入技术。然而，这种「通用性」雄心以环境为代价：这些系统需要大量能源，也排放大量碳。本文首次系统比较各类 ML 系统的推理成本，既包括任务专用模型（即只执行单一任务的微调模型），也包括「通用」模型（即为多任务训练的模型）。作者以「在代表性基准数据集上完成 1,000 次推理所需的能源与碳」度量部署成本，发现多用途生成式架构在多种任务上比任务专用系统贵几个数量级，即使控制模型参数量也是如此。作者最后讨论当前部署多用途生成式 ML 系统的趋势，提醒应更有意识地权衡其效用与能源、排放成本的增加。研究全部数据可通过交互式演示访问。

**关键词/CCS**：机器学习、神经网络、环境影响、功率估计与优化。

## 1. 引言（第 2 页）

理解不同行业的环境影响是制定减缓策略的第一步。对信息与通信技术（ICT）这类较新的行业（AI 与 ML 属于其中），仍需更多工作理解其环境影响的范围与影响因素。2017—2021 年，Meta、Amazon、Microsoft 与 Google 这四家主要商用云计算提供商的用电量翻了一倍多 [22]。按最新数据，全球数据中心用电近年每年增长 20%–40%，已达全球电力需求的 1%–1.3%，2022 年占能源相关温室气体排放的 1% [21]。但 AI 部门对这些数字的具体贡献仍不清楚。

近期记录 ML 环境影响的文献，大多聚焦量化训练阶段的运行能耗与碳 [12,30,41,49]，因为该阶段单模型能耗较易测量，且单次训练耗能惊人 [41,49]。然而，推理等生命周期其他阶段的环境影响可能与训练相当甚至更大，因为大规模部署现代模型需要大量计算资源。虽然单个样本的推理计算量远小于训练同一模型，但推理发生的频率高得多——为 Google 翻译这类热门产品提供支持的模型，每天推理可达数十亿次。然而，量化模型推理与部署成本的深入研究有限，其能源、碳以及水和稀土矿产消耗的影响仍待估计。据全球最大云服务商 AWS，推理估计占 ML 云计算总需求的 80%–90% [2,28]；Meta 2021 年的文章称其内部端到端 ML 碳足迹约三分之一来自推理，其余来自数据管理、存储与训练 [57]；Google 2022 年的研究则称其 ML 能耗的 60% 来自推理、40% 来自训练 [40]。鉴于 AI 模型部署日益普遍，必须超越这些高层统计，更具体地了解不同模型与任务推理的能源需求与碳排放。特别是，从推理而非训练角度看，「多用途/通用」这一点会得出截然不同的结论：仅看训练成本，为多任务训练一个模型确实可能更节能；但考虑到这些模型在聊天、网页搜索等面向用户的应用中会进行大量推理，这些收益在模型生命周期内很容易被抵消甚至逆转。

为厘清这一问题，作者做了大规模测量，评估各类 ML 模型与架构（包括大语言模型）部署所需能源。据作者所知，这是首个只聚焦 ML 生命周期推理阶段的研究。研究覆盖 5 种模态、10 个任务、30 个数据集上的 88 个模型，分析终端任务、模态、模型规模、架构与学习范式（任务专用或多任务/多用途）对能效的影响。作者发现，不同模型、模态与任务之间每次推理的能耗相差数个数量级，并揭示多用途系统的收益、能源成本与随之而来的碳排放之间的重要取舍。通过更细致地刻画 ML 推理能耗的巨大差异，作者希望本研究能帮助从业者理解跨任务与跨模型的精度—效率取舍，并支持部门层面的更好估计、预测与政策决策。

## 2. 已有工作（第 3 页）

估计 ML 模型的能源与排放仍是相对冷门的题目，但自 Strubell 等（2019）量化多种当时大型 NLP 模型能耗与碳排放的开创性文章以来，关注度逐渐上升。此后多数研究聚焦估计神经网络训练阶段的能耗与碳排放，包括 Patterson 等（2021、2022）比较不同模型并分析影响排放的因素；也有针对特定架构的研究，如 BLOOM [31] 与 Noor [27]，深入分析模型生命周期各步骤及其对最终碳排放的相对贡献。鉴于 ML 模型越来越多地部署在云上，一些研究关注云上减排方式，如延迟调度、负载弹性与选择碳强度最低的电力 [6,12,19]。

尽管有这些实证研究，目前仍缺少量化与比较 ML 模型能耗和碳排放的标准化方法。已有 Code Carbon [47]、MLCO2 [26]、LLMCarbon [13] 等工具，但方法不同、输出不同（详见 [1] 的比较），因此难以系统比较不同模型的碳足迹。现有工具与研究也大多只关注动态功耗（即为硬件供电所需电力）及其排放；也有一些提议把 ML 模型的隐含排放（可归因于计算设备制造的排放）纳入估算，但受 GPU 等常用计算硬件设计方缺乏透明度所限。近期估计显示，在 Meta 计算集群上训练并部署的 LLM，其隐含碳足迹可占碳足迹的 50% [57]。

多数既有工作聚焦训练，因为它在模型生命周期中较易处理（通常在特定计算实例上于固定时段完成）；推理也开始成为研究对象 [6,11]。Luccioni 等对 BLOOM 的研究首次考察部署 LLM 的具体能源成本 [31]，发现随时间推移，推理可占模型总碳足迹的相当大一部分。本研究进一步深入推理阶段，通过在不同任务与数据集上测试多种架构，更好理解可观察到的差异程度，以及看似微小的用户选择如何造成模型环境影响的巨大差异。

## 3. 方法（第 3–5 页）

### 3.1 任务与数据集选择（第 4 页）

作者从 5 种模态中选择 10 个 ML 任务：文本→类别（文本分类、token 分类、抽取式问答）、文本→文本（掩码语言建模、文本生成、摘要）、图像→类别（图像分类、目标检测）、图像→文本（图像描述）与文本→图像（图像生成）。选择这些任务，是因为它们在自然语言处理与计算机视觉中都很常见，可探索多种模态，并包含若干多模态任务（图像描述与图像生成），以考察模态之间的联系。每个任务取 Hugging Face Hub 上三个下载量最高的数据集（表 1）。

**表 1 中译。任务与数据集。** 图像分类：CIFAR-10、CIFAR-100、ImageNet-1K；问答：SQuAD、SQuAD v2、SciQ；图像描述：Visual Genome、RedCaps、COCO；摘要：SAMSum、CNN-Daily Mail、XSum；图像生成：DiffusionDB、ImageReward、SD Prompts；文本分类：IMDB、Rotten Tomatoes、SST-2；掩码语言建模：BookCorpus、C4、OSCAR；文本生成：WikiText、BookCorpus、OSCAR；目标检测：Visual Genome、CPPE-5、COCO；token 分类：ReCoRD、WikiANN、CoNLL 2003。

### 3.2 模型（第 4–5 页）

为覆盖广泛的部署用例，作者抽取 88 个模型：有些为所选任务专门训练或微调，有些设计为零样本或多任务模型，从而既能比较同一任务上的不同架构，也能比较同一架构在不同任务间的表现。

**任务专用模型。** 对上述每个任务，选取 Hugging Face Hub 上按下载量最受欢迎的 8 个模型（完整列表见补充材料表 6）。对每个模型，用 Transformers 库 [55] 在其训练任务对应的 3 个数据集上各做 1,000 次推理；每组推理重复 10 次以保证统计显著性。推理按顺序执行（不做批处理），以反映模型在真实场景中部署的波动性——真实部署中往往难以对模型输入做批处理。

**多用途模型。** 另选 8 个多用途模型（专为在多种应用场景中表现良好而训练）：Flan-T5 系列 [8] 中 4 个不同规模的序列到序列模型（base、large、xl、xxl），以及 BLOOMz 系列 [34] 中 4 个仅解码器模型（BLOOMz-560M、1B、3B、7B）。在任务子集上测试，以比较多用途生成模型与任务专用系统的能耗与排放：问答、文本分类与摘要。选这三个任务，是因为能找到可用统一架构完成它们的模型集合（并非所有任务都可行，尤其涉及多模态的任务）。对这 8 个模型采用跨模型一致的零样本提示（如「Summarize the following text: [text]. Summary:」），在与微调模型相同的 1,000 个样本上测试，每个实验同样重复 10 次。

全部实验在 AWS 上一个含 8 块 NVIDIA A100-SXM4-80GB GPU 的节点上运行，用 Code Carbon 包 [47] 测量推理能耗与碳排放。由于所有实验都在同一计算区域（AWS us-west-2，位于俄勒冈州，平均碳强度 297.6 gCO₂e/kWh），推理能耗与碳排放相关，因此作者视讨论重点选择绘制其一。推理能耗在其他区域用 A100 部署时大致相同，但碳排放会随当地电源而变；分别报告能源与碳有助于跨地区、跨硬件比较。实验代码与 Code Carbon 日志已公开，日志不仅给出总能耗，还按硬件部件（GPU、CPU、内存）细分为进一步分析提供依据。全部模型实验与评估共消耗 754.66 kWh 能源，排放 178.97 kg CO₂e。

## 4. 结果（第 5–13 页）

### 4.1 任务专用模型分析（第 5–7 页）

表 2 给出 10 个任务在所有模型、1,000 次推理上的平均能耗与标准差。图像与文本分类任务处于排放谱的低端（1,000 次推理 0.002–0.007 kWh），而文本生成与摘要等生成任务平均耗能高 10 倍以上（约 0.05 kWh/1,000 次），图像描述与图像生成等多模态任务最高（0.06–2.9 kWh/1,000 次）。总体而言，文本任务比图像任务更节能：图像分类（中位数 0.0068 kWh/1,000 次）比图像生成（1.35 kWh）耗能少；反之，文本生成（0.042 kWh）比文本分类（0.0023 kWh）耗能多。作为参照，给平均智能手机充电需 0.022 kWh [51]：最高效的文本生成模型完成 1,000 次推理的能耗相当于一次手机充电的 9%，而最低效的图像生成模型相当于 522 次手机充电（11.49 kWh），即每生成一张图约半次充电——不过图像生成模型之间差异也很大，取决于生成图像尺寸。

**表 2 中译。10 个任务每 1,000 次查询的平均能耗与标准差（kWh）。**

| 任务 | 均值 | 标准差 |
|---|---|---|
| 文本分类 | 0.002 | 0.001 |
| 抽取式问答 | 0.003 | 0.001 |
| 掩码语言建模 | 0.003 | 0.001 |
| token 分类 | 0.004 | 0.002 |
| 图像分类 | 0.007 | 0.001 |
| 目标检测 | 0.038 | 0.02 |
| 文本生成 | 0.047 | 0.03 |
| 摘要 | 0.049 | 0.01 |
| 图像描述 | 0.063 | 0.02 |
| 图像生成 | 2.907 | 3.31 |

由此，完成同样次数推理的能耗在不同模型间可相差 1,450 倍以上。直观上这与模型的决策空间相符：从情感分析这类二分类任务（只能输出 0 或 1），到文本生成与摘要模型的整个词表。生成长度也影响能耗：文本生成平均比掩码语言建模耗能多 15 倍，因为后者只生成一个 token，而本文设置中文本生成对每个输入生成 10 个新 token，且随新 token 生成，输入长度不断增长（每个 token 序列都要回灌模型以生成后续 token）。图像任务抽象层次更低、决策空间更大（生成原始像素而非文本 token），因此更耗能：图像分类比文本分类耗能多 3 倍以上（0.007 对 0.002 kWh），图像生成平均比文本生成耗能多 60 倍以上（2.9 对 0.047 kWh）。

图 2 给出 5 种模态下模型规模（参数量）与每 1,000 次推理碳排放（g CO₂e）的关系。模型规模与推理排放确实相关，且各模态的增长趋势不同；但任务结构解释的变异多于模型规模。文本到图像仍是碳与能耗最高的任务：约 5 亿参数的较小图像生成模型（如 segmind/tiny-sd）产生的碳比文本到类别模型多几个数量级（1,000 次推理 100 g 对 0.6 g）。文本到文本任务中可见两组模型：掩码语言建模趋势较低，排放接近文本到类别模型；文本生成与摘要则与参数量相近的图像描述模型相当。作为参照，碳强度最高的图像生成模型（stable-diffusion-xl-base-1.0）1,000 次推理产生 1,594 g CO₂e，约等于平均汽油乘用车行驶 4.1 英里 [51]；碳强度最低的文本生成模型（distilbert-base-uncased）产生的碳相当于同类车辆行驶 0.0006 英里，即少 6,833 倍。当 Dall·E、MidJourney 这类图像生成模型被部署到面向全球数百万用户的应用中时，这一差距会迅速累积。

本分析的高层结论是：即使只针对单一任务训练的模型，任务内部差异也很大，不同模态任务之间差异更大。本质上，把图像和文本输入映射为类别输出的任务，比生成文本或图像的任务更省能、更少碳。认清这些区别有助于制定减缓 AI 环境影响的相关政策，因为这种差异有时可达数个数量级。

### 4.2 多用途系统的环境成本（第 8–11 页）

本部分比较两类多任务模型：BLOOMz 系列的仅解码器模型与 FLAN-T5 系列的序列到序列模型，考察不同参数量模型在不同任务上的能耗强度与碳排放。选取文本分类、抽取式问答与摘要三个任务（因其多样性与广泛适用性），在每任务相同的 3 个数据集上比较 8 个不同规模的零样本模型。

**4.2.1 任务专用与多任务架构的排放。** 图 3 按数据集给出各模型平均每次查询排放。对两个判别式任务——情感分析（SST-2、Rotten Tomatoes、IMDB）与问答（SciQ、SQuAD、SQuAD v2）——任务专用判别模型（蓝色）的排放明显低于多用途序列到序列（黄色）与仅解码器生成模型（绿色）。由于纵轴为对数坐标，差异达数个数量级：例如在 SciQ 上，最高效的任务专用模型 1,000 次推理排放 0.3 g CO₂e，而多用途模型同任务排放 10 g。这符合模型结构的直觉：二分类文本分类模型在二维向量上做 softmax 预测类别，而多用途模型要生成「positive」或「negative」，预测基于整个词表，自然更耗能。对生成式任务摘要（SAMsum、XSum、CNN-Daily Mail），任务专用与多用途模型排放较接近：任务专用序列到序列模型 1,000 次推理 4–10 g，多用途模型 20–30 g；差异主要来自模型规模——所考察的任务专用摘要模型最多 6 亿参数，而多用途架构可达 110 亿参数。

作者还评估了两类模型的性能可比性：任务专用模型用 evaluate 库 [52]，零样本模型用 LM Evaluation Harness [14]。但用同一指标比较二者本身困难：任务专用模型决策空间小得多（如二分类只有两类），多用途模型输出词表大，且依赖提示模板与策略。作者通过使用两个标准化工具包、并保持零样本提示一致，尽量使评估标准化。

图 4 聚焦文本分类，展示模型规模（横轴，对数）、准确率（纵轴）与排放（点大小，对数）的关系。任务专用编码器模型中准确率差异较大：若干规模相近、排放相近的小模型准确率相差很大；多用途模型准确率差异较小，总体平均准确率更高。序列到序列与仅解码器模型排放相当（均比任务专用模型高数个数量级）。中型多用途模型（约 30 亿参数）准确率可能略优于更大与更小的模型，但鉴于多用途 LLM 评估的诸多限定，这一差异未必显著。其余两个任务的完整评估结果见补充材料 B。

**4.2.2 多用途架构内部的差异。** 表 3 显示，在同一架构家族内（仅解码器或序列到序列），规模与排放相关，模型越小排放越少、能耗越低；但同等规模下序列到序列比仅解码器更高效：例如 Flan-T5-XL 与 BLOOMz-3B 规模相近（约 30 亿参数），前者 1,000 次推理平均少排 2 g。Flan-T5-XXL 是所测多用途模型中参数量最大者（110 亿），排放却低于更小的 BLOOMz-7B（平均 11.48 g）。按任务看（图 5），零样本模型与任务专用模型呈现相同模式：文本分类碳强度低于问答，摘要在三者中最高。序列到序列模型（圆点）的任务间差距较小，仅解码器模型（叉号）的任务间差异更明显。

| Flan-T5-xl | 2.8B | 8.08 | 0.058 | BLOOMz-3B | 3B | 10.17 | 0.073 |
| Flan-T5-xxl | 11B | 11.48 | 0.083 | BLOOMz-7B | 7B | 14.46 | 0.104 |

对表 3 的关系可作如下解释：在摘要等任务上，解码器模型确实比同规模序列到序列模型排放更多；但在问答与文本分类上，两种架构排放相近。这同样可用注意力机制解释：序列到序列模型生成答案时只关注输入的最后一层，而仅解码器架构要对整个序列关注所有层，导致运算量更依赖输出长度，输出较长的任务排放更多。

表 4 与图 6 进一步验证这一直觉：虽然模型与数据集之间有差异，但输出长度分布与任务类别的预期一致——输出越长排放越多，仅解码器模型尤甚。图 6 深入展示摘要任务中平均输出长度、碳排放与模型结构的关系，显示输出长度与排放明显相关，且仅解码器架构（BLOOMz 系列）的斜率高于序列到序列架构（Flan-T5 系列）。因此，多用途模型同样没有「一刀切」模式，其排放与能耗差异可归因于模型规模、输出长度等因素，部署时需更审慎地选择。

### 4.3 训练与推理成本比较（第 12–13 页）

一个重要取舍是：推理成本何时与训练（及微调）成本持平？即模型部署耗能何时等于初始训练？这通常难以比较，因为需要 ML 生命周期各步骤的总能耗，而这很少可得。本研究所考察的模型里，BLOOMz 与 Flan-T5 系列的论文都未报告训练总能耗或碳排放。但 BLOOMz 是原始 BLOOM 系列的微调版本 [56]，可依据 BLOOM 碳足迹估计论文作者提供的日志 [31]，并加上微调能耗（据 BLOOMz 论文 [34] 的训练日志估计，但缺少推断碳排放所需信息）。表 5 给出这些数字与每次推理平均能耗：每次推理能耗从最小模型 BLOOMz-560M 的 5.4×10⁻⁵ kWh 到最大模型 BLOOMz-7B 的 1.0×10⁻⁴ kWh。这与 Luccioni 等报告的 BLOOM-176B 平均每次查询 0.004 kWh 相符——后者约大 25 倍，单次查询能耗高 40 倍，尽管那还包括模型的 API 部署，而本研究不含。

## 5. 讨论（第 13–14 页）

由于 LLM 推理的分布式特性（相比训练在时间与地点上相对受限），相关能耗与碳排放研究有限，难以在不同模型与任务间做有意义比较。本研究尽量保持参数稳定，包括代码、硬件、数据集、批大小与 Python 库，并公开全部代码与交互工具。主要结论如下：

- **生成式任务比判别式任务更耗能、更多碳。** 如图 1，最耗能耗碳的是生成新内容的任务：文本生成、摘要、图像描述与图像生成。
- **涉及图像的任务比纯文本任务更耗能耗碳。** 具体而言，预测类别的任务（文本到类别、图像到类别）比生成图像的任务（如文本到图像）耗能少，涉及文本的任务介于两者之间（图 2）。
- **同规模、同任务下，仅解码器模型比序列到序列模型略更耗能耗碳。** 表 3、图 3 与图 6 显示仅解码器任务需要更多计算（能源），输出较长的任务尤甚；这一观察值得在其他架构、任务与数据集上验证。
- **训练仍比推理耗能耗碳数个数量级。** 表 5 首次给出 BLOOMz 不同规模模型训练、微调与推理的相对能耗，发现训练/微调与推理的持平点随模型规模增大而增加。虽然单次训练对应数亿次推理，但鉴于 ML 模型部署之普遍，许多热门模型很快就能达到这一持平点。
- **用多用途模型做判别式任务，比用任务专用模型更耗能。** 文本分类（IMDB、SST-2、Rotten Tomatoes）与问答（SciQ、SQuAD v1/v2）差距尤其大，摘要（CNN-Daily Mail、SamSum、XSum）差距较小。如表 4，输出越长，多用途与任务专用模型的差距越大。

作者认为最后一点最具启发性，因为当前正从「为特定任务微调的小模型」转向「一次完成多种任务、实时响应用户查询的模型」。这一转变自 GPT-3 [5] 展示语言模型少样本/零样本学习潜力以来，既发生在 ML 研究中，也发生在消费场景：GPT-4、PaLM 等 LLM 被部署到网页搜索 [4,18]、邮件与导航 [17] 等面向用户的产品中，而这些场景此前多用 BERT 等较小任务专用模型 [3,16]。由于科技公司对参数量、架构与碳排放缺乏透明度，难以量化这一转变的环境影响，但可基于本研究实验做比较：例如为抽取式问答微调的 BERT 模型（bert-large-uncased-whole-word-masking-finetuned-squad，类似抽取式网页搜索任务）每 1,000 次查询平均排放 0.70 g CO₂e，不到多用途模型（Flan-T5 base 2.36 g、BLOOMz-560M 2.34 g）的 3 倍；若比较文本分类等任务，差距更悬殊：bert-base-multilingual-uncased-sentiment 每 1,000 次查询仅 0.32 g，而 Flan-T5-XL 为 2.66 g、BLOOMz-7B 为 4.67 g。作为参照，2022 年发布的首个 PaLM 有 5,400 亿参数 [7]，GPT-3 有 1,750 亿参数 [5]。作者认可生成式零样本模型执行多任务的能力，但在任务明确的场景（如网页搜索与导航），鉴于其能源需求，并未看到部署必要性的有力证据。

本研究旨在为理解 ML 生命周期中常被忽视的最后一步——模型部署——的能源需求与碳排放奠定基础。4.3 节的训练、微调与推理能耗比较，据作者所知是首次同类比较，为理解 ML 模型生命周期各阶段能耗如何累加铺路。这些数据点可帮助 AI 研究者、从业者以及正在估计与监管 AI 及 ICT 环境影响的政策制定者。作者承认研究不代表所有部署情境与约束，意图是建立初始数据点并为测试比较其他模型奠定基础。研究还指出许多未来方向：架构选择、蒸馏等技术、参数量、硬件选择、数值（浮点）精度等都会影响推理效率。作者鼓励继续分析开源模型，同时指出模型架构与训练细节日益缺乏透明度，使这类工作以及机器学习公平与问责相关研究越来越难开展。

## 在 A 题中的用法

1. **统一任务量的分母。** 全文的核心口径是「每 1,000 次推理的能耗与碳」，且推理按顺序执行、不批处理。第一问把园区负载折算成 IT 用电时，应固定任务类型、模型与输入输出长度，再用本表的 kWh/1,000 次乘以请求量；不同任务之间的 1,450 倍差异说明不能用一个「平均每次推理」代替。
2. **PUE 要另乘。** 本文测的是 8×A100 节点在 us-west-2 的能耗，未乘数据中心 PUE；第一问得到 IT kWh 后，还需乘 PUE（本文场景可参考 Xiao 等的 1.1–1.58）才是设施用电，再乘电网水/碳强度。
3. **任务结构比模型规模更能解释差异。** 生成式任务比判别式贵 10 倍以上，图像生成又是文本生成的 60 倍。若案例园区以推理服务为主，应把「生成式请求占比」作为情景变量，而不是只调模型大小。
4. **训练与推理的持平点可用于第二问。** 单模型训练/微调成本约等于 2–5.9 亿次推理；若任务可迁移到别的地区执行，迁移节省的每次推理碳/水乘以请求量，可与迁移的通信、延迟成本比较。注意本文的持平点只算能耗，不含硬件制造与网络。
5. **给 WAICO 的论据。** 「每 1,000 次文本分类 0.002 kWh、每 1,000 次图像生成 2.9 kWh」是很好懂的量级对比；可据此建议对高耗能的生成式服务做能效披露或分级，而不是笼统限制 AI 算力。
