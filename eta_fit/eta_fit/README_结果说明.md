# 算力与功率关系：可复现拟合

原始数据共 96 条，使用两列均为正且有限的 76 条记录，排除 20 条无正值配对记录；不删除离群点。原始论文仅作为背景阅读，未修改。

## 结果

拟合方向为 O_proxy = η_proxy × P_reported，采用过原点最小二乘：η_hat = Σ(P_i O_i)/Σ(P_i²)。这直接估计算力对功率的效率参数。

- η_proxy = 1053.788305 H100-equivalent/MW = 1.053788 H100-equivalent/kW。
- 将算力方向的拟合关系代数反解：P_reported（kW）≈ O_proxy / 1.053788 ≈ 0.948957 O_proxy。此处功率仍为原数据报告功率，非已验证的 IT 功率；下述主模型 R² 衡量算力方向的拟合。
- 95% 配对 bootstrap 区间：[0.932966, 1.160718] H100-equivalent/kW（10,000 次，固定随机种子）。
- 中心化 R² = 1 − SSE/Σ(O_i−均值)² = 0.894784。建议正文引用这个值。
- 非中心化 R² = 0.945947，不可与通常带截距回归 R² 混用。
- 带截距对照：O_proxy = 1065.994289 P_reported + (-4626.042398)，R² = 0.895007。
- 留一交叉验证 R² = 0.877831；逐个删除样本的 η 范围为 [1.029263, 1.114894]。
- 直接拟合 P 对 O 与将本拟合代数反解不同：直接过原点回归的 R² = 0.886204，隐含 η = 1.114003 H100-equivalent/kW。本文主模型是 O 对 P 的回归，不混用两种回归的斜率与 R²。

## 能支持什么结论

若 η 定义为 O_out/P_IT，则 P_IT = O_out/η 是定义的代数改写。真正待检验的假设是不同设施及工况下 η 是否近似固定。横截面线性相关不能证明因果关系、单设施负荷曲线或效率永远不变。

CSV 的 Current H100 equivalents 是容量代理指标，缺少负载率、持续实测吞吐量及精度/任务口径；Current power (MW) 未明确区分设施总功率、IT 功率和实测平均功率。因此本程序估计的是 η_proxy，不能直接宣称得到真实 IT 持续算力效率。不同项目可能共用推算系数，源数据中的 Calculations sheet 和 Selected Sources 需要后续核验，相关性可能部分来自数据生成方法。Bootstrap 假定记录独立，不能覆盖共享来源造成的系统误差。

若验证 P_reported 为 IT 功率且 O_proxy 可作为持续算力，才可条件性使用 η_IT≈η_proxy。若验证功率为设施总功率，且 PUE=k 恒定、持续输出为容量的 u 倍，则 η_IT = u·k·η_proxy；未提供 k、u，不能擅自指定。若各中心 k、u 不同，应逐条修正后重新回归，不可只乘一个统一系数。H100-equivalent 不是 FLOP/s，缺少其定义时不转换。

## 可放入论文的文字

为检验固定效率近似，我们将数据中心的 H100 等效容量作为算力代理指标，对报告功率进行过原点最小二乘拟合。在 76 个正值样本中，估计 η_proxy=1.0538 H100-equivalent/kW，中心化决定系数 R²=0.8948，表明容量与报告功率在样本内具有较强的近似比例关系。该结果为固定效率的简化建模提供经验依据，但由于原始数据缺少持续输出和 IT 功率的统一计量口径，不能将其视为对真实持续算力效率的直接测定。应用 P_IT=O_out/η 前，需统一设备、利用率和功率边界，并对 η 作敏感性分析。

安装：`python -m pip install -r requirements.txt`；运行：`python fit_eta.py`。可用 `--csv 路径` 指定新数据。默认使用本目录保留的原始 CSV 副本。图为英文以便论文使用；PNG 为 320 dpi，PDF/SVG 为矢量格式。results.json 保存完整精度与原始文件 SHA-256；sample_audit.csv 保存逐条纳入规则；fitted_data.csv 保存预测值与残差。
